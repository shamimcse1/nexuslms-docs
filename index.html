📘Introduction

NexusLMS is a corporate training platform: a Laravel backend with an admin panel and a learner web portal, a REST API, and a Flutter mobile app for iOS and Android. Admins build courses, quizzes and assignments and assign them to departments; employees learn in the browser or on their phone.

  • Admin panel (/admin): courses, modules and lessons, quizzes, assignments and grading, learning paths, live classes, certificates, departments, users, roles and permissions, notifications, reports and settings.
  • Learner portal (/portal): employees take courses, quizzes and assignments, join live classes, view and print certificates, and verify credentials in the browser.
  • REST API (/api/v1): token-based API used by the mobile app.
  • Mobile app: the learner experience on iOS and Android, including push notifications.

This documentation is for version 1.0.0. It is a single page that opens offline from the documentation folder.

It is also online, always in its latest version, at shamimcse1.github.io/nexuslms-docs. Use the search box at the top of the menu (or press /) to find any topic.

Want to look around first? Open the live demo's admin panel or learner portal, or install the Android demo app. The sign-in pages show the demo accounts; click one to fill it in. The demo's data resets every 15 minutes.

Quick start

Setting up takes five steps. Click a step to jump to its instructions.

  1. Install the backendInstall the PHP packages, build the web assets, upload the files and run the web installer.
  2. Set up the admin panelSign in, set your site name, logo and time zone, then add departments, people and courses.
  3. Connect emailA mail server is needed for password resets. Push notifications are optional.
  4. Build the mobile appSet your API address, rename the app, change the icon and build it.
  5. Go liveWork through the going-live checklist before inviting people.

Requirements

  • Server: PHP 8.3 or newer with BCMath, Ctype, cURL, DOM, Fileinfo, Filter, Hash, JSON, Mbstring, OpenSSL, PCRE, PDO, PDO MySQL, Tokenizer and XML; MySQL 8.0+ or MariaDB 10.6+; Apache or Nginx with the document root on public; HTTPS; a cron job. Composer 2 and Node.js 20.19+ or 22.12+ are needed to install, not to run. No queue worker is needed.
  • Mobile app: Flutter 3.44 or newer (Dart 3.12+). Android Studio with Android SDK 36; the app runs on Android 7.0 (API 24) and newer. A Mac with Xcode 16+ and CocoaPods for iOS; the app runs on iOS 15 and newer.
  • Accounts: a mail (SMTP) provider; a Firebase project if you want push notifications (optional); a Google Play developer account and the Apple Developer Program to publish the app.

🖥️Backend & admin panel

The backend in main/backend is a Laravel 13 application. It serves the admin panel at /admin, the learner portal at /portal, the REST API at /api/v1 and the web installer at /install.

Installation

  1. Upload the contents of main/backend to your server, for example to /var/www/nexuslms.
  2. Point your domain's document root to the public folder inside it.
  3. Install the PHP packages: 
    cd /var/www/nexuslms
composer install --no-dev --optimize-autoloader
  4. Build the web assets (CSS and JavaScript): 
    npm ci
npm run build
  5. Make the storage and cache folders writable by the web server: 
    chmod -R 775 storage bootstrap/cache
chown -R www-data:www-data storage bootstrap/cache
    (Use your web server's user instead of www-data if it differs.)
  6. Create an empty MySQL database and a database user with full access to it.
  7. Open https://your-domain.com/install in your browser and follow the web installer.

Web installer

  1. Requirements: checks the PHP version, extensions and folder permissions. Fix anything marked red before continuing.
  2. Database: enter the database host, port, name, user and password. The installer tests the connection and saves it to .env.
  3. Migrate: creates the database tables. The Import demo data option adds sample courses, learners and content. Leave it off on a live site: the sample accounts use publicly documented passwords.
  4. Administrator: choose the site name, URL and your own administrator name, email and password.
  5. Finish: the installer switches the site to production mode (APP_ENV=production, APP_DEBUG=false), links the public storage folder and locks itself. Sign in at /admin.
If you imported demo data, change the passwords of the sample accounts (or delete them) under Admin → Users before inviting real learners.

For a public demo site only, set DEMO_MODE=true in .env to show the sample sign-in accounts on the login pages. It is off by default.

Scheduler (cron)

Live class reminders (every 5 minutes), due date and certificate expiry reminders (once a day at 08:00) and the weekly cleanup of replaced assignment files run through the Laravel scheduler. Add this single cron entry on your server:

* * * * * cd /var/www/nexuslms && php artisan schedule:run >> /dev/null 2>&1

Everything else works without it. No queue worker is required: push notifications and emails are sent right after each request finishes.

Email

Password reset emails need a working mail server. Set these values in .env (your provider gives you them):

MAIL_MAILER=smtp
MAIL_HOST=smtp.your-provider.com
MAIL_PORT=587
MAIL_USERNAME=your-username
MAIL_PASSWORD=your-password
MAIL_ENCRYPTION=tls
MAIL_FROM_ADDRESS="learning@your-company.com"

You can also enter these in Admin → Settings → SMTP Email Server. Values saved there are used instead of the .env values; leave the host empty to keep using .env. Send Test Email sends a real email and shows the mail server's error if it fails.

The reset link opens /portal/reset-password, where learners choose a new password. It works for both the portal and the mobile app.

Local testing and demo mode

To try NexusLMS on your own computer:

cp .env.example .env
composer install
npm install && npm run build
php artisan key:generate
php artisan serve

Create an empty database, open http://127.0.0.1:8000/install and tick Import demo data in step 3 to get sample courses and the demo accounts. The installer switches the site to production mode; for local debugging set APP_DEBUG=true in .env afterwards. Set DEMO_MODE=true to show the demo accounts on the sign-in pages (only for a public demo site).

Going-live checklist

  • APP_URL is your https:// address, APP_ENV=production and APP_DEBUG=false (the installer sets these).
  • Demo data is off, or the demo accounts are deleted or have new passwords; DEMO_MODE is off.
  • Email works: send a test from Admin → Settings → SMTP Email Server.
  • The cron entry is installed (Scheduler).
  • Uploaded images load (run php artisan storage:link if not).
  • Your administrator account uses a strong, unique password.
  • Caches are built: php artisan optimize.
  • The mobile app's API_BASE_URL uses https://, and release builds are signed (Release builds).
  • Database and storage backups are scheduled.

Updating to a new version

  1. Back up your database and the .env file and storage folder.
  2. Upload the new files, keeping your .env and storage folder.
  3. Run: 
    composer install --no-dev --optimize-autoloader
npm ci && npm run build
php artisan migrate --force
php artisan optimize:clear

Settings

Open Admin → Settings to set up the platform. Each tab is shown below.

Privacy & Support holds the IT Help Desk details (email, phone, help center link and support hours) and your privacy policy. In the mobile app, IT Help Desk on the sign-in screen lists the contacts you fill in, and Privacy Policy opens the policy inside the app. The policy is also published at https://your-domain.com/privacy-policy, which you can use as the privacy policy link in the App Store and Google Play. Who can open what

Each admin page needs a permission, and each role holds a set of permissions that you can change under Admin → Roles & Permissions. A Super Admin always has every permission. The defaults are:

RoleDefault access
Super AdminEverything, including Roles & Permissions.
Company AdminEverything except Roles & Permissions. Cannot create, edit or delete Super Admin accounts.
ManagerView users, manage departments, view courses and assign them, learning paths, view certificates and live classes, reports (view, export, reminders) and announcements.
InstructorCreate and edit courses, quizzes (including short-answer review), grade assignments, host live classes and take attendance, view reports.
EmployeeThe learner portal and mobile app only, and only the courses they are enrolled in (or courses that allow self-enrollment).

A role you create yourself can open the admin panel as soon as it has at least one permission. Giving permissions to the Employee role lets every learner into the admin panel, so leave it empty.

Lesson files and assignment submissions are stored privately in storage/app/private. Learners reach them only through authenticated stream and download routes that verify active course enrollment on every request.

First-time setup

  1. Settings → General & Branding: site and company name, logo and favicon.
  2. Settings → Time Zone: choose your time zone before you schedule live classes or set due dates.
  3. Settings → SMTP Email Server: mail settings, then send a test email.
  4. Departments, then Users: add people one by one or import a CSV file (download the sample from the Users page). Each imported person is emailed a link to choose their own password, so set up email first; anyone who misses it can use Forgot password on the sign-in page.
  5. Courses: create a course, add modules and lessons, add quizzes and assignments, publish it and assign it to departments or people.

Key design decisions

  • One users table for admins and learners; what each person can do comes from their role and its permissions (spatie/laravel-permission). A Super Admin always has every permission.
  • Every admin page is mapped to a permission in one place, and a test fails if a new page is added without one.
  • Learners only reach courses, lessons, quizzes, assignments and live classes they are enrolled in or invited to; the API and the portal share the same checks.
  • Lesson files and submissions are stored privately; media stream and download endpoints verify authentication and active enrollment on every request.
  • The mobile app signs in with Laravel Sanctum tokens.
  • Push notifications and emails are sent right after each request finishes, so no queue worker is needed.
  • Lesson text written by admins is cleaned before it is shown, so scripts cannot run.

API

The mobile app uses the API at https://your-domain.com/api/v1. Learners sign in with POST /api/v1/auth/login and receive a bearer token, which is sent as Authorization: Bearer <token> on every other request. Sign-in and password reset requests are rate limited.

Signed-in requests are limited to 120 per minute; sign-in to 5 attempts per minute.

HomeGET dashboard, GET system/config

Learning pathsGET learning-paths, learning-paths/{slug}

CertificatesGET certificates, certificates/{number}

📱Mobile app: setup and running

  1. Open main/mobile in Android Studio or VS Code.
  2. Create your settings file from the example and set your API address: 
    cp assets/.env.example assets/.env
    API_BASE_URL=https://your-domain.com/api/v1
    If assets/.env is missing, the app uses the values in assets/.env.example. Out of the box that points to the live demo server (https://nexuslms.dev-shamim.com/api/v1), so you can run the app and sign in with a demo learner account before you set up your own server.

    Set API_BASE_URL to your server's address followed by /api/v1:

    • Live server: https://your-domain.com/api/v1 (use HTTPS; Android blocks plain HTTP in release builds).
    • Android emulator with a server on your computer: http://10.0.2.2:8000/api/v1.
    • iOS simulator with a server on your computer: http://127.0.0.1:8000/api/v1.

    After changing it, stop the app and run it again; a hot reload does not pick up .env changes.

  3. Install packages and run: 
    flutter pub get
flutter run

What the app looks like

Testing on a real phone

On a phone on the same Wi-Fi as your computer, use your computer's network address, for example http://192.0.2.10:8000/api/v1, and start Laravel with php artisan serve --host=0.0.0.0. Plain http:// works only in debug builds; release builds need https://.

File structure

The app in main/mobile is organized by feature. Each feature has the same three layers, so once you know one feature you can find your way around all of them.

lib/core/configenv.dart reads API_BASE_URL from assets/.env.

lib/core/networkThe API client (api_client.dart), the list of API addresses (api_endpoints.dart) and the response format.

lib/core/errorTurns network and server errors into the messages people see.
lib/core/ui, lib/core/utilsNavigation and snackbar helpers, and safe reading of JSON values.
lib/shared/widgetsWidgets used on many screens: cards, buttons, search field, logo, icons, and the loading, empty and error views.
lib/features/<feature>One folder per part of the app: auth, splash, home, dashboard, courses, player, quiz, assignments, certificates, live_classes, notifications, profile and support.

…/<feature>/domainentities (the plain data the screens use), the repository interfaces, and logic such as filtering and progress.
…/<feature>/presentationbindings (create the controller), controllers (GetX state), screens, widgets, and the screen's text in a *_strings.dart file.

android, iosPlatform projects: app name, package name and bundle ID, launcher icons, permissions and signing.
test180 tests, laid out like lib, plus architecture_test.dart, which checks that the layers above stay separate.

To add a screen, copy the layout of an existing feature: add its route name in lib/core/constants/app_routes.dart and register the screen and its binding in lib/app.dart.

✏️Rename the app and package

App name

  • Android: change android:label in android/app/src/main/AndroidManifest.xml.
  • iOS: open ios/Runner.xcworkspace in Xcode, select the Runner target and set Display Name on the General tab (this writes CFBundleDisplayName in ios/Runner/Info.plist).

Package name (Android) and bundle ID (iOS)

  • Android: change applicationId and namespace in android/app/build.gradle.kts, then move MainActivity.kt to the matching folder under android/app/src/main/kotlin/ and update its package line.
  • iOS: in Xcode, select the Runner target and change Bundle Identifier under General → Identity. Choose your team under Signing & Capabilities.

🎨Icon, colors and font

  • App icon: replace assets/app_icon/icon.png (1024×1024, no transparency) and assets/app_icon/icon_foreground.png (the Android adaptive icon foreground, with transparent padding), then run dart run flutter_launcher_icons.
  • Colors: edit lib/core/constants/app_colors.dart.
  • Web logo: the admin panel, portal, installer and certificates use the same logo as the app unless you upload your own in Admin → Settings. To change the built-in one, replace backend/public/assets/images/brand/logo.svg (and favicon-32.png and apple-touch-icon.png in the same folder, plus public/favicon.ico). A favicon uploaded in Admin → Settings takes priority in the browser tab.
  • Font: the app bundles Inter in assets/fonts/inter. To use another font, add its files there, update the fonts section of pubspec.yaml, and change fontFamily in lib/core/constants/app_text_styles.dart.

🚀Release builds and signing

Android

  1. Create an upload key (keep this file and its passwords safe): 
    keytool -genkey -v -keystore ~/upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
  2. Create android/key.properties: 
    storePassword=your-store-password
keyPassword=your-key-password
keyAlias=upload
storeFile=/path/to/upload-keystore.jks
    storeFile is the full path to the keystore you created. On Windows, use forward slashes, for example C:/keys/upload-keystore.jks. Never commit key.properties or the keystore; both are already in android/.gitignore.

    You don't need to edit any Gradle file. android/app/build.gradle.kts already reads key.properties and signs release builds with it. Without the file, release builds fall back to the debug key, which Google Play does not accept.

  3. Build the app bundle for Google Play: 
    flutter build appbundle --release

iOS

  1. Open ios/Runner.xcworkspace in Xcode, select the Runner target, and under Signing & Capabilities choose your own team and bundle ID.
  2. Push notifications need the Push Notifications capability, which requires a paid Apple Developer account. On a free personal team, remove Runner.entitlements from the target to build without push.
  3. Build the archive for App Store Connect: 
    flutter build ipa --release

🔔Push notifications (optional)

NexusLMS works without Firebase. Learners still see every notification in the app's notification list; Firebase adds pushes to the phone's lock screen.

1. Create a Firebase project

  1. Create a project in the Firebase console.
  2. Add an Android app with your package name (the same applicationId as above) and click Register app.
  3. Download google-services.json and put it in mobile/android/app/, next to build.gradle.kts.
  4. Add an Apple app with your bundle ID, then download GoogleService-Info.plist into mobile/ios/Runner/.
  5. For iOS, open Project settings → Cloud Messaging, select your Apple app and upload an APNs authentication key (.p8) from your Apple Developer account.

The build picks these files up automatically. Without them, the app builds and runs with push turned off.

2. Connect the server

  1. In the Firebase console, open Project settings → Service accounts and click Generate new private key (a JSON file). Keep this file private.
  2. In Admin → Settings → Firebase, enable push, upload or paste that JSON file, and choose which events send a push: course assignment, assignment grading, certificates and live class reminders.

🧰Troubleshooting

Frequently asked questions

Does it run on shared (cPanel) hosting?

Yes, as long as the host offers PHP 8.3+, MySQL, a cron job and symbolic links (for php artisan storage:link). You can run composer install and npm run build on your own computer and upload the result if the host has no terminal. A VPS works too.

Do I need a queue worker or Redis?

No. Emails and push notifications are sent right after each request finishes, so only the cron job is needed.

Is the mobile app required?

No. Learners can do everything in the browser through the learner portal. The app is an extra way to learn on the phone.

Do I need Firebase?

Only for push notifications. Without Firebase, the app and the website work normally and people still get email and in-app notifications. See Push notifications.

Can learners sign up by themselves?

No, this is a company platform: admins add people under Admin → Users. When you add one person you choose their first password and they get a welcome email; people added by CSV import get an email with a link to choose their own password.

How do I point the app at my server?

Set API_BASE_URL in main/mobile/assets/.env to your site's address followed by /api/v1, then stop and run the app again. See Mobile app setup.

How do I change the name, logo and colors?

For the website, use Admin → Settings → General & Branding (see White-labeling). For the app, see Rename the app and package and Icon, colors and font.

Should I import the demo data on my live site?

No. Demo data is for trying the platform: the sample accounts use publicly documented passwords. Leave it off in the installer, or delete those accounts before you invite real people.

📧Support

If you run into a problem or have a question, many answers are already in Troubleshooting & FAQ.

For anything else, use the Support tab on the NexusLMS item page on CodeCanyon. Item support follows Envato's item support policy: questions about the item and fixes for reported bugs. Customization, installation on your servers, and third-party services such as your mail provider, Firebase, Apple and Google Play accounts are outside item support.

To help us answer quickly, tell us:

  • what it is about: the backend and admin panel, the learner portal or the mobile app, and Android or iOS;
  • the exact error message, and the step or command that caused it;
  • your versions: the NexusLMS version (at the bottom of the admin menu), php -v for the backend and flutter --version for the app;
  • for a server error, the last lines of storage/logs/laravel.log, with passwords and keys removed;
  • what you have already tried from this documentation.
